# Read-only cross-agent workspace audits

Use when comparing another agent's configuration, skills or extensions for selective Hermes adoption.

1. Resolve the active Hermes profile and the exact source roots. Inventory bounded metadata first. Exclude dependency trees, VCS internals, transcripts, diaries, memory records, credentials and caches unless necessary and explicitly scoped.
2. Separate checkout declarations, installed artifacts, enabled settings, effective runtime activation and successful live behavior. File presence is not activation; a skill is not an authenticated integration; scheduler rows are not successful runs. A Windows checkout inspected from WSL does not establish a WSL runtime install.
3. Parse mixed JSON/YAML settings locally and redact secrets before tool output. Inspect credential presence or key names only. Never echo raw settings/auth files, execute credential helpers, or copy auth state between agents. A tracked literal in a credential-named field is a potential exposure, not proof of a live or publicly leaked key.
4. Avoid integration setup prompts during an audit. Read integration skill files as audit data where loading would trigger credential prerequisites. If a prompt appears, dismiss/stop setup and explain that no secret is required. Do not invoke account-connected diagnostics without separate authorization.
5. Parallelize independent source audits with exact roots, read-only constraints, excluded data, and distinct sanitized artifact paths. Require file-level evidence and machine-readable inventories. Verify child claims against key source files and parse counts, rather than trusting summaries.
6. Trace explicitly configured plugins to manifests and entrypoints without importing them. Distinguish bundled/default-enabled manifests from actual runtime activation. Query scheduler metadata using read-only DB connections; do not export payloads or historical execution content.
7. Compare patterns against the existing Hermes inventory and live official docs. Prefer existing native tools plus a narrow skill over a foreign extension rewrite. Keep identity, project rules, user preferences, procedures, task state and evidence in their respective stores. Do not bulk-import personal memory or create writable cross-agent symlinks.
8. Rank candidates by the user's intended job. For work productivity, prioritize capture, cited retrieval, commitments, review and controlled writes; keep coding-only frameworks in the coding agent. Treat corporate-to-personal exports and future desktop/auth access as separate approval boundaries.
9. Deliver a short prioritized recommendation plus a detailed local report and reconciled inventories. State what was checked, what remains unverified, what changed, and what requires approval. A proposed workflow is not a tested integration. Do not migrate config or schedule jobs as a side effect of the audit.
10. For later implementation, verify an actual read-only workflow before external writes or scheduling. Check exact destination state after writes; after ambiguous responses, inspect before retrying. Cron delivery must match the user's actual surface—plain CLI has no push-delivery channel.
